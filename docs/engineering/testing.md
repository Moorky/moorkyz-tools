# Testing and verification

Use observable tests and isolated temporary directories. Never test cleanup
against personal directories, installed programs, real history or downloaded
media. Directory Cleaner fixtures must verify archive bytes, Keep priority,
date/size boundaries, no overwrite, stale plans and symlink rejection.

```powershell
pnpm build
pnpm check:repository
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm test:unit
pnpm test:browser
pnpm check:source
pnpm audit --audit-level=moderate
pnpm check
```

`pnpm check` runs read-only repository syntax/structure checks, configured
formatting, lint, tests/build, browser/axe, portal type and bounded source checks.
`pnpm test:unit` includes storage/runtime and isolated deployment tests; it does
not rebuild generated assets, so run `pnpm build` first when changing sources.
Source/ZIP tests run after assets have been generated by build.
The compact toolbar generator has exact escaping/URL and output-size tests;
the removed SDK's coverage and consumer-fixture jobs are not active gates.

Optional native VideoCrunch gates:

```powershell
pnpm test:videocrunch
node --test tools\videocrunch\test\media.test.js
pnpm test:videocrunch:browser
```

The real-media suite needs Windows PowerShell, yt-dlp and FFmpeg. The default
Directory Cleaner engine tests use synthetic local files and built-in Node APIs,
without privileged operations or third-party dependencies.

Report exact commands and observed `PASS`, `FAIL`, `NOT RUN` or `N/A` in a
task-specific audit. Automated tests are not independent security, manual
accessibility, clean-VM, container or production readiness certification.
