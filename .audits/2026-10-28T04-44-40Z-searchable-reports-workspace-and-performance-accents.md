## 1. Request and outcome

- Requested behavior: report messages match their item's performance accent; Reports page initially shows Diagnostics and Statistics before its primary report list; each summary can hide/show and the list can move to the top. Search and report ID, timestamp, success, elapsed, video length, file size, UI time and background time are required.
- Implemented behavior: separate Reports navigation/page; expanded native Diagnostics/Statistics sections; reversible Reports-to-top action; shared literal AND/phrase/exclusion/level search grammar and 1-10 result cap. Read-only results expose all requested fields, newest starts first, with UTC timestamps and exact report paths in tooltips. New reports measure window-active versus inactive/minimized task time. Optional supplied video/file measurements display real values; missing/legacy measurements explicitly display Unavailable.
- Performance policy: prior successful reports of the exact launcher/project/task form the baseline, excluding current/later/failed results. Faster <=90% is green; Typical >90% through 110% neutral violet; Slower >110% through 125% amber; Much slower >125% red. Failures are always red; absent/zero baseline is neutral. Report body/message uses the same brush as the row accent, while timestamp/level/ID retain semantic colors. This is comparison, not a quality certificate.
- Acceptance criteria/evidence: actual native fixture verifies initial/reversed section order, toggles, no idle writes, real persisted outcomes, every report field, background accounting during minimization, old absent metadata, optional supplied values, prior-only grade samples, exact grade boundaries, row/message brush equality, ID/phrase/level/exclusion queries, cap/full match count, stale-query cancellation, malformed metadata/XML failures and recovery, linked-path refusal and unchanged report bytes.
- Intentional exclusions: no VideoCrunch-specific instrumentation or media probing, CPU/worker execution attribution, hosted processing, report-file rewriting, numerical score, filesystem watcher, persistent layout preferences or additional package. Existing Logs & Errors remain together with their own searches. This task colors measured report items, not arbitrary unmeasured child-process messages.
- Relevant decisions/contracts: [root contract](../AGENTS.md), [current product decisions](../src/docs/decisions/decision-register.md), [GUI guide](../src/.moorkyz/gui/README.md). Clarification tool returned user unavailable; selected generic command reports with truthful Unavailable fields and window-active timing, and documented a pragmatic historical comparison policy.

## 4. Risk and quality review

- Public contract/default/compatibility: new additive page and XML `uiSeconds`/`backgroundSeconds`; old version-1 reports remain readable without inventing fields. Optional `videoDurationSeconds`/whole-byte `fileSizeBytes` are consumed only if supplied, never inferred by scanning user files. Foreground/background refer to this window's activation, not browser time, media playback, CPU or worker scheduling.
- Security/privacy/permissions: no new external integration, dependency or automatic service. Only local control-center report paths are read. Root/reparse checks precede enumeration/read; malformed XML has no external entity resolver/DTD and a 1MiB parsing bound. Report labels are redacted; contents become WPF text, not executable markup.
- Accessibility/keyboard/reduced motion: named query/list/actions, native accessible expanders, Enter result selection and Escape clear, visible focus, labeled outcomes/ratings plus colors. Existing reduced-motion terminal tests pass. Reordering retains the same controls and focus; no nonessential report animation introduced.
- Disabled/idle behavior: no report scan on construction or filesystem watcher. Reports load on explicit navigation, Refresh/query, and task completion only while page visible. No saved history/settings are created by viewing. Timers/cancellation disposed on close.
- Error handling/cleanup/recovery: no silent partial-success lists. Invalid outcomes, nonfinite/negative measurements, fractional file sizes, mismatched UI/background totals, unsupported XML, malformed files and linked folders expose path-bearing errors and unavailable statistics. Correct affected input and Refresh recovers. No samples yield explicit unavailable values. Synthetic tests now preserve the original failure text and wait boundedly for an already-running fixture command before cleanup, without re-executing the action.
- Performance/regression: scan parses complete local history to calculate prior-only baselines, even when UI cap is small; can be expensive at large scale. UI creation is bounded by the shared hit cap. Raw saved files are never rewritten by browsing/grading/search. Timing is monotonic, guarded, and capped so foreground plus background equals task duration.
