## 1. Request and outcome

- Requested behavior: choose a straightforward place for Diagnostics/Statistics without hiding/reordering; fix the reported `moorkyz start` root-package failure; open GUI from the beginning instead of a terminal action menu.
- Implemented behavior: compact always-visible summary panels above Reports, side by side at >=700 logical content pixels and stacked below that width. Removed summary expanders/reorder button. In this Windows checkout, bare/start/launch open GUI before checks; a hidden `__startup` worker runs the existing bounded file/stack/dependency checklist with full logs/reports. Project actions remain gated until success; failure provides a visible Retry startup checks button. GUI children explicitly set `MOORKYZ_HEADLESS=1` to avoid recursive windows and keep service semantics. RUN prefers the windowed EXE or uses a hidden PowerShell bootstrap; shortcuts target that bootstrap, not `cmd /k`. EXE is Windows subsystem 2, captures child errors and uses a native bootstrap-failure dialog.
- Acceptance criteria/evidence: actual native windows opened/closed for bare/start/launch/RUN and the rebuilt actual EXE using isolated incomplete-checkout fixtures; failed preflight exposed Retry with no root package/script execution or printed console menu. Separate passing worker fixture verified startup action gating/unlocking and the headless child environment. Existing CLI worker/service tests pass. Native resize checks verify wide side-by-side/narrow stacked summaries; screenshots inspected. `node .\moorkyz list` resolves portal to `src\packages\portal` with the expected port.
- Intentional exclusions: no profile changes or global command installation, hosted/deployment changes, service auto-start, policy bypass or machine prerequisite installation. An existing terminal used to type a command is not forcibly closed. Explicit `gui` remains an idle inspection command; help/doctor/run/other CLI management commands remain console-capable. `MOORKYZ_HEADLESS=1` deliberately preserves automation and old console service/menu behavior; `launch --check` remains console-only/non-installing. Outside this Windows checkout portable behavior remains unchanged.
- Relevant decisions/contracts: [root contract](../AGENTS.md), [current product decisions](../src/docs/decisions/decision-register.md), [shared startup](../src/.moorkyz/scripts/README.md#shared-startup), [GUI guide](../src/.moorkyz/gui/README.md).

## 4. Risk and quality review

- Public contract/default/compatibility: Windows checkout launch aliases now mean open GUI, not run a root service script. Shared startup remains bounded two-attempt logic, including approved frozen dependency restoration; machine/global prerequisites never auto-install. CLI automation must opt into `MOORKYZ_HEADLESS=1`; internal GUI worker/service calls set it explicitly. `--check` output/exit behavior preserved. No service is selected automatically.
- Security/privacy/permissions/secrets: no new packages/accounts/network integrations, execution-policy bypass, signing, elevation or deployment. Child processes use explicit executable/argument handling and no arbitrary GUI shell action. Bootstrap failures are visible in EXE/native dialogs; full startup output stays local. Existing redaction/path protections remain passing.
- Accessibility/keyboard/reduced motion: summary headings remain readable/named and always present, native wrapping adjusts with width. Removed redundant hide/reorder controls. Existing terminal focus, read-only controls, source navigation, keyboard selection and reduced-motion behavior remain passing. No independent certification.
- Disabled-feature resources/network behavior: inspection `gui` remains idle; GUI-first entrypoints intentionally run only local startup checks after the window loads. Actions are gated until checks pass. No automatic services or remote connections. Tests open real native windows against synthetic roots only and close them with bounded cleanup.
- Error handling/cleanup/recovery: failed preflight produces error tasks/full diagnostic report and visible Retry instead of exiting before GUI. Failed full-log setup also exposes Retry without starting checks. Nonzero EXE bootstrap propagates details via native dialog; `--check` retains captured diagnostic output and exit status. Hidden PowerShell launch wrapper surfaces runtime errors; policy restrictions remain respected. Existing generated EXE was moved to a named backup before promoting the validated new artifact; no overwrite or deletion.
- Dependency/performance/regression: stack pins unchanged, no prerequisite installation performed by this task. Startup work runs off UI thread with captured child output. Report summaries use natural content sizing; resizing coverage verifies no forced hidden state. Native suite uses short bounded state checks rather than re-executing actions.
